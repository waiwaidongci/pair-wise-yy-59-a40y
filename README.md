# pair-wise-yy-59 法律文件披露、去密与发布质控工作台

用于诉讼披露批次中的区域去密、原页/发布页双人复核、文档标签和发布门禁。PDF.js 真实渲染示例文档，去密区域可绘制、确认并持久化到本地草稿。

## 技术栈

React、Radix UI 风格组件、Zustand、TanStack Router、TanStack Query、PDF.js、Vite、TypeScript。

## 运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62059`。示例 PDF 由浏览器端生成后交给 PDF.js 渲染，不需要外部文件。

```bash
npm run build
```

## 版本化协作模型

文档（去密区域、密级、复核结论）与批次发布资格之间是版本化协作关系，核心实现在 `src/versioning.ts`（纯逻辑）与 `src/store.ts`（装配、持久化、跨标签页同步）。

- **即时失效与版本上调**：任一文档的去密区域、密级或复核结论保存后，文档版本号 +1，关联批次的发布资格立即重算；复核结论按其针对的版本盖章（`reviewedVersion`），文档升级而结论未更新即判过期，旧版本文档不能通过批次门禁。
- **两个标签页并发编辑**：每个标签页持有各自的工作副本（未保存草稿）。保存时若对方已先保存，按共同基线做三方合并——只合入无冲突字段；同一字段/同一区域两边都改且结果不同时，字段冻结为先保存者的值并在"并发合并裁决"面板中保留两份原文，由人工选择采用哪一方，绝不静默覆盖。一方删除、一方编辑同样保留两份。
- **裁决**：所有冲突逐一裁决后才算"完整合并"，版本随每次裁决上调；在那之前文档状态为"待裁决"，批次保持阻塞。复核类冲突裁决后结论必须重做。
- **旧稿升级**：无版本号的旧持久化数据（v1）在加载时迁移：回填 v1 版本号与字段修订索引，原有去密区域、密级与复核结论全部保留，并据此建立批次资格。
- **可恢复快照与重试**：每次提交都在文档上保留提交前快照与双方字段（`recovery`），可"用快照重试合并"或"回滚到提交前快照"（回滚也产生新版本，版本号保持单调）。批次重算失败时保留上一份资格快照并支持一键重试；完整合并前或资格非 publishable 时，批次不能标记可发布。批次页提供"重算失败演练"按钮验证该路径。
- **跨标签页同步**：通过 `storage` 事件接收其它标签页的已保存事实（文档/批次），本标签页的绘制与草稿状态不被覆盖；顶部徽标实时显示待裁决数。
